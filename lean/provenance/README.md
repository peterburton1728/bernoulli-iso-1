# Algebraic source and release transformations

OpenAI's characteristic-two direct-finiteness construction supplies the algebraic
existence data used by this Bernoulli conjugacy. The immutable upstream revision
is `adc7f1241b42e322a6451854ab7e4b4c146bf78a` in
[OpenAI/math](https://github.com/openai/math/tree/adc7f1241b42e322a6451854ab7e4b4c146bf78a).
The upstream mathematical witness is credited to OpenAI, not to this project.

The records in this directory describe successive stages; their hashes refer
to those exact stages rather than interchangeable copies:

- `upstream-source-manifest.json` identifies the original upstream modules,
  retrieval locations, sizes and SHA256 hashes at the pinned commit.
- `port-manifest.json` and `lean-435-compatibility.patch` record the probability
  API adaptation from the older Lean/Mathlib interface to Lean 4.35.0. The finite
  uniform law and the counting argument retain their mathematical meaning.
- `split-bundle-manifest.json` records the upstream bundle partition, source
  boundaries and hashes before the release's module-system presentation changes.
- `release-transformation.json` records the frozen checkpoint identity and
  per-file original/release hashes, relocation and module-visibility changes.
  Regenerate this record after the last release-source edit.

The release uses Lean's `module` format, public imports and an exposed public
section where clients need definition bodies. `UpstreamConstruction` uses
`backward.privateInPublic` to export private simp auxiliaries generated by the
legacy proof during the module migration. This is a visibility compatibility
setting, not an extra mathematical axiom. The transformation record should
account for these changes; do not call differently hashed release bytes
byte-identical to their upstream originals.

The standalone Challenge states the dynamical conclusion without importing
these project-specific sources. The Solution imports their proof development
and adapts the closed certificate to that independent statement. The source
trace does not extend the certificate to all bases or finitary continuity.

To verify provenance, start from a trusted copy of the pinned upstream and
source manifests, check the original hashes, apply/review the recorded API
port and bundle transformation, and then check the final release hashes.
A manifest copied together with altered source is not an independent trust
anchor. Fresh builds, proof-term axiom checks and protected statement comparison
remain separate requirements. No execution result is asserted by this record.
